# AGENTS.md – GPIB-Adapters

Family repo of GPIB (IEEE-488) adapters that plug straight into an instrument's GPIB socket: USBGPIB-STM32 (USB on
an STM32F103) and LANGPIB-WCH (Ethernet/PoE and USB on a WCH CH32V407). Both run the shared, board-independent
firmware in `gpib-core/` (descended from xyphro's UsbGpib, MIT). Public repo.

## Layout

| Folder | Holds |
|---|---|
| `gpib-core/` | shared firmware (`src/`), simulated bus and instrument (`sim/`), host tests (`test/`), host server (`host/`), Python checks (`tools/`) |
| `USBGPIB-STM32/` | `Firmware/` (Makefile, `src/`, submodules in `lib/`), `bootloader/dapboot` (submodule), `Hardware/` (KiCad, production), `Enclosure/`, `web/` (WebUSB flasher site), `tools/`, `docs/` |
| `LANGPIB-WCH/` | `Firmware/` (app, `bootloader/`, submodules in `lib/`, `tools/`), `Hardware/` (KiCad, production), `Enclosure/`, `tools/`, `docs/` (incl. `handoff.md`, `production-log.csv`) |
| `.github/workflows/pages.yml` | CI: builds and tests both firmwares and the web flasher; a `v*` tag makes a release |

## Build and test

Clone with `git clone --recurse-submodules`.

```
make -C gpib-core test                       # host unit tests on a simulated bus
make -C USBGPIB-STM32/Firmware               # arm-none-eabi-gcc; build/usbgpib.bin
make -C USBGPIB-STM32/Firmware bootloader    # dapboot
make -C USBGPIB-STM32/Firmware test
make -C LANGPIB-WCH/Firmware                 # xPack riscv-none-elf-gcc 15.2.0-1 (found in ~/opt); build/langpib.dfu
make -C LANGPIB-WCH/Firmware test
cd USBGPIB-STM32/web && npm ci && npm test   # web flasher
```

Flashing, bring-up and production targets: `USBGPIB-STM32/README.md`, `LANGPIB-WCH/docs/firmware.md`.

## Rules

- **gpib-core is a root folder that boards build against by relative path** (`GPIB_CORE := ../../gpib-core`), not a
  submodule. Reason: family-repo decision (owner, 2026-11-05, Tools-KiCad `docs/new-repo.md`).
- **A gpib-core change: run `make test` there, build each board's firmware, commit them together.** Reason: both
  boards compile it (`gpib-core/README.md`).
- **Builds use `-Wall -Wextra -Werror`, nothing suppressed** (`gpib-core/README.md`).
- **Refactors must prove binaries unchanged:** `tools/build_hashes.sh` on a `git archive HEAD` copy and on the
  working tree; every hash must match (the script copies the submodules `git archive` leaves out). Scope: changes
  meant to leave either firmware or bootloader alone. Reason: identical images need no bench test, and an unchanged
  `dapboot.bin` means no bootloader rewrite on update.
- **Board (KiCad) work follows Tools-KiCad** (`../Tools-KiCad/AGENTS.md`, `docs/new-repo.md`); the schematics and
  boards are generated by its `projects/usbgpib-stm32/` and `projects/langpib-wch/`. **Enclosure work follows
  Tools-CAD** (`../Tools-CAD/AGENTS.md`, `projects/USBGPIB-STM32/`, `projects/LANGPIB-WCH/`). Reason: the rules and
  scripts live there.
- **`Firmware/` and `Hardware/` stay capitalised** (an exception to the lowercase folder rule in the owner's repo
  setup doc). Reason: Tools-KiCad and Tools-CAD project scripts, the submodule paths and CI point at them (2026-11-22).
- **Public repo:** run Tools-KiCad's personal-data scan (`docs/new-repo.md` §4) before pushing; docs must not send
  readers to the private Tools-KiCad / Tools-CAD repos; every submodule must stay public. Vendor PDFs stay local
  (`.gitignore`). Reason: Tools-KiCad `docs/new-repo.md` §4.
- **Releases:** push a `v*` tag; CI builds both firmwares and publishes a GitHub Release (`pages.yml`).

## Learnings

Learning loop: before reporting done, record what this session taught here (or in the board's `docs/`), each lesson
with its scope and reason; delete lessons whose reason no longer holds. Board and enclosure lessons go into
Tools-KiCad / Tools-CAD under their own learning loops.

- **USBGPIB-STM32: SW1 enters DFU only when held at reset, and only dapboot reads it; the app must not poll it.**
  Reason: owner request (2026-11-22); a press while running used to drop the adapter into dapboot. USB entry
  (DFU_DETACH, `++dfu`, `!reset`) stays in the app.
- **USBGPIB-STM32: change dapboot (its source or `BOOT_DEFS`) only when needed.** Reason: any change to `dapboot.bin`
  makes every board rewrite its bootloader pages on the next app update, and a power loss then needs SWD
  (`docs/firmware.md`).
